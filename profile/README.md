<h2>一、九项参数先摆到明面上</h2>
<p>常年盯海外平台数据的人，日常动作其实很固定：早上开后台看指标，白天跑几轮采集，晚上核对异常日志。这套动作对网络的要求不是「快」，而是「每次都一样」。所以下单之前该问的是参数，不是单价。</p>
<h3>参数分四组来看</h3>
<p>第一组出口参数，决定平台看到你是谁；第二组会话参数，决定这个身份能维持多久；第三组计费参数，决定钱怎么算；第四组服务参数，决定出问题时多久恢复。前三组是硬指标，可以直接测；第四组偏软，但最影响长期体验。</p>
<h3>哪几项必须落到合同里</h3>
<p>出口类型、粘性策略、换线规则、退款口径，这四项口头承诺没有意义。落地方式很简单：让对方把参数填在你发过去的表里，回传签字或盖章的版本。后面扯皮时，这张表比任何聊天记录都管用。</p>
<h2>二、出口参数：ASN 与归属地决定第一印象</h2>
<p>住宅段和机房段的最大差别在 ASN 归属。平台侧不一定明说，但地址挂在运营商名下还是挂在云厂商名下，判定逻辑完全不同。拿到线路第一件事不是登录，是查下面这几项。</p>
<h3>ASN 名称里藏着关键信息</h3>
<p>用 ipinfo.io 的 asn 字段或 bgp.he.net 查，返回名称里出现 hosting、cloud、datacenter、server、vps 这类词，基本可以按机房段处理。反过来是 Comcast、AT&amp;T、Verizon、Deutsche Telekom 这类运营商，才算真家宽。中间还有一层叫双 ISP 归属：ipinfo 里 company 与 asn 两个字段指向同一家运营商，这种线路在平台看来最自然。</p>
<h3>归属地精度要到城市级</h3>
<p>只写「美国」没有意义。账号资料填洛杉矶，出口落在达拉斯，虽然同属一国，但时区和使用节奏都对不上。建议要求城市级归属，同批号尽量落在同一城市圈，跨州来回跳动比换 IP 本身更容易被注意到。</p>

<h2>三、会话参数：粘性时长比带宽重要</h2>
<h3>粘性会话拉多长合适</h3>
<p>默认十分钟粘性适合爬页面，不适合账号运营。注册、邮箱验证、订阅扣费这几个环节中间要跳好几个域名，十分钟往往不够。建议账号相关操作把粘性拉到三十至六十分钟，接口批量调用按任务粒度设置，跑完一轮再释放。</p>
<h3>切换粒度按账号而不是按请求</h3>
<p>按请求轮换是采集玩法，用在账号上等于每次刷新都换城市，很容易触发验证。正确做法是一个账号绑一条出口，调度层用账号 ID 做键，把映射写进配置表并强制生效。这条规则听着简单，靠人记是记不住的。</p>

<h2>四、计费与服务参数：钱花在哪要说清</h2>
<h3>三档计费的计量口径不一样</h3>
<p>按量通常按流量 GB 或请求数结算，适合波动大的短期项目；包月按线路条数算，用不用都收；独享按并发占用小时计，介于两者之间。同一个团队完全可以同时用两档——采集走按量，账号走独享，别硬凑成一档。</p>
<h3>换线规则是服务质量的试金石</h3>
<p>问三个问题：单条故障多久内替换、整批换线是否另计费、替换后的归属地还在不在原城市。自营线路一般能承诺三十分钟响应、同城替换；转售渠道多数只能说「尽快」。这一项差别，用半年就能明显感觉到。</p>

<h2>常见问答</h2>
<h3>住宅 IP 的粘性时间可以自己调吗？</h3>
<p>答：多数服务商后台提供档位切换，常见有按请求、十分钟、三十分钟、按账号固定几档。能不能自定义要看产品形态，独享线路一般更灵活。选之前先问清最小切换单位，这直接决定账号会不会在操作中途换城市。</p>
<h3>同一个城市的不同 ISP 混着用有问题吗？</h3>
<p>答：问题不大，但最好一个账号始终对应一家 ISP。平台侧看的是地址变更轨迹，同一城市两家运营商之间来回跳，仍会留下不一致的记录。批量开户时按 ISP 分组，比随机取线更省心。</p>
<h3>双 ISP 归属信息对不上该怎么处理？</h3>
<p>答：先看是不是查询口径差异，用 ipinfo 和 ipapi 交叉核对一次。两边都显示 company 与 asn 不同源，就要求服务商换线，别自己改环境去凑。归属信息本身就是线路质量的一部分。</p>
<h3>按量计费和包月，长期盯数据选哪个？</h3>
<p>答：看每天的在线时长。一天用不满三小时，按量更划算；超过八小时且并发稳定，包月或独享单价更低。折中办法是先按量跑一个月，用后台的时段分布图判断，再决定换不换档。</p>
